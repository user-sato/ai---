# 04 Google Drive連携と月次フォルダ

> この文書は旧Node/PostgreSQL案の詳細設計を含む。現行GAS運用の週次・日次出力はDrive上のMarkdownであり、設定は[`gas/README.md`](../gas/README.md)を正とする。

## 推奨フォルダ構成
```text
LINE AI書記Bot/
└── 1月イベント/
    ├── 00_プロジェクト現況書                 [Google Docs / 常設]
    ├── 00_タスク・課題管理                   [Google Sheets / 常設]
    ├── 2026/
    │   ├── 2026-11/
    │   │   ├── 2026-11_月次まとめ           [Google Docs]
    │   │   ├── 週次レポート/
    │   │   │   ├── 2026-11-02_11-08        [Google Docs]
    │   │   │   └── 2026-11-09_11-15        [Google Docs]
    │   │   └── 補足資料/                    [必要時]
    │   └── 2026-12/
    │       ├── 2026-12_月次まとめ           [Google Docs]
    │       └── 週次レポート/
    └── 2027/
        └── 2027-01/
```

## 月次フォルダのルール
1. 月替わりの定期処理で翌月フォルダを作る（必要なら初回メッセージ到着時にも遅延作成）。
2. **週次レポートの格納月は期間の開始日（月曜）の月**。月をまたぐ週も一つのレポートにする。例: 2026-11-30〜12-06は`2026-11`に格納。
3. **月次まとめは暦月単位**（毎月1日00:00〜翌月1日00:00、JST）。
4. 常設の現況書・Sheetsは月別フォルダに移動しない。月をまたぐ未完了タスクを一貫管理する。
5. 月フォルダ名は`YYYY-MM`、年フォルダ名は`YYYY`。表示名変更に依存せずGoogle file IDをDBに保存。
6. 同じ月のフォルダや同じ週のDocsを重複作成しない。DB登録とDrive検索の双方で確認する。
7. フォルダだけ作成して、会話がない月の空レポートは原則作成しない（設定可能）。

## Docs / Sheets構成
- 常設Docs：概要、確定事項、未決事項、タスク概要、最終更新時刻。
- 月次Docs：総括、決定事項、進捗、未解決事項、次月への持越し、関連週次Docsリンク。
- 週次Docs：期間、差分、確定事項、タスク変更、残課題、確認待ち、根拠。
- Sheets: `Tasks`、`Issues`、`Decisions`、`SyncStatus`。各行に内部ID、状態、更新日時を含む。

## 同期アルゴリズム
1. DBで対象プロジェクトと期間のスナップショットを確定。
2. `drive_folders`で対象フォルダIDを取得。なければDriveに作成して登録。
3. `document_registry`でGoogleファイルIDを取得。なければ作成して登録。
4. DBから文書全体または対象範囲を生成し、ハッシュで前回との差分を判定。
5. 差分があればDocs/Sheets APIへ反映し、同期成功時刻・ハッシュ・revisionを記録。
6. API失敗時は指数バックオフで再試行。成功するまでLINEへ完成通知を出さない。
7. Driveで手編集された文書はMVPでは取り込まない。生成物に「Bot管理・手動編集は次回同期で上書きされる可能性」を明示。

## 認証・権限
- 個人Google Driveへの作成は、管理者OAuth認可（最小スコープ）を基本案とする。
- 共有ドライブを利用できる組織ではサービスアカウント方式を検討。
- リンク共有を無条件に公開しない。グループ参加者の閲覧権限付与方法を事前に決める。
- Google API認可情報はSecret Manager等で保管。
