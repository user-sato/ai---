# MVP実装判断と検証計画

## 設計整合性
- 文書02/05の週次境界の差は文書09の明示的な優先方針で解決する。日曜20時JSTの速報版、前回cutoffから今回cutoffまで。初回のみ当週月曜00時。格納月は今回配信週の月曜の月。本文には連続集計の実際の期間を表示する。
- 文書04の「月替わりに翌月」は文書05/09の毎月1日00:10に新月作成と解釈する。
- 月次通知なし、OAuth、設定された管理者だけ承認。保存期間、閲覧者、予算は未確定。本番接続前に運用者が決める。

## 技術判断
- DB inbox/outboxをCloud Tasksの前段に置く。Webhook中はDB保存のみ。毎分のdispatcherがDBの未処理ジョブをTasksへ送り、解析は5分単位に集約する。キュー登録失敗でも受信データは消えない。ローカルは同じworkerを直接実行する。
- 決定/タスク/課題は共通のItemテーブル(kindで区別)とEvidenceで管理する。承認・根拠・重複排除・監査を同じトランザクションで扱い、型ごとの状態をサービスで制約する。論理テーブル名からの物理実装差分であり、業務上の区分は維持する。
- 1グループだけ明示的にseed登録。未登録グループの自動収集は禁止。DBのproject単位advisory transaction lockでworkerを直列化。外部APIにはタイムアウトを設定する。
- 抽出は上限付きバッチ。根拠引用は原文との完全一致、IDはバッチ内で検証。担当・期限・金額の構造化推測は採用せず、MVPの担当/期限はNULLを維持。AI提案は人間承認まで未確定。既存候補と同タイトルは追加根拠だけを結合し、自動上書きしない。
- レポート本文はDBから決定論的に生成し、AIによる二次要約の事実混入を避ける。AI抽出に由来する各項目は根拠と状態を明示する。
- Drive作成物にappPropertiesの管理キーを付けて再発見。設定されたroot以下のBot専用新規ファイルのみ更新する。既存ファイルを名前で流用しない。公開共有は作らない。
- Google失敗時はDBジョブに指数バックオフを保存。Docsと常設ファイル成功後、通知outboxを永続化する別ジョブに移行。LINE retry key(UUID)を永続化し、24時間の有効期限を超える前(23時間)に不明状態の再送を停止し要手動確認にする。
- 安全な初期値はDRY_RUN=true。実接続は運用同意と環境変数の明示設定が必要。dry-runは実ファイルID/本番ジョブ成功として保存しない。

## 依存順・完了条件
M1: schema/migration → raw署名検証 → DB inboxとjobの同一TX。再送/不正署名/未登録グループをテスト。
M2: Zod検証 → evidence照合 → 候補保存 → 管理者承認/却下・監査。推測非確定、根拠不正、同一タスク、権限をテスト。
M3: OAuth adapter → 管理キー付きフォルダ/Docs/Sheets → 一方向同期。月替わり、月跨ぎ、更新/再試行をテスト。
M4: cutoff/週次/月次 → reportの一意性 → 通知outbox。ゼロ会話、締切直後、Docs失敗、再送をテスト。
M5: OIDC → backoff/lock → ログ秘匿/消去手順 → dry-run/デプロイ手順。DB統合テストとbuild/typecheckを完了する。

## 本番前の未決事項
保存期間・削除依頼窓口、予算とアラート閾値、Google閲覧者、LINE承認者。デフォルトで自動削除・公開権限変更はしない。手動上書き、権限公開、本番デプロイは本実装作業では実施しない。

## 補足実装差分
- Message.weeklyReportIdで週次への割当を記録し、古い日時で遅延到着した発言も次の週次に取り込む。遅延件数を表示する。過去の未完成週次があれば後続を延期する。
- Google Docs/SheetsのAPI呼出はgoogleapis、LINEはSDKのリクエスト型を使うタイムアウト付きfetchアダプタ。SDKクライアントのHTTP中断指定がないため30秒のAbortSignalを優先する。retry key/受付済み409を明示処理する。
- AI出力にも8192 completion tokensの上限を設け、モデル固有のtemperature対応に依存しない。
- 状態表示は文書生成時点であり、過去時点の完全なイベントソーシングは実装しない。対象期間の発言と新規確定数を集計し、各項目の更新/確定時刻を明示する。
- M5の削除は原文の墓標とBot管理生成物の再生成。バックアップやGoogleの変更履歴・既送信LINEまでの自動完全消去は保証せず、管理者手順で補う。
- 担当者・期限の自動抽出/修正UI、高度なAI差分要約、自動期限通知、管理者への独自外部障害通知は未実装。状態・根拠・新規項目の決定論的な集計とCloud Monitoring手順で補う。
