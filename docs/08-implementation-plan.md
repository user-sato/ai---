# 08 実装計画と受入条件

> **アーカイブ:** この文書のM1〜M5は旧Node/PostgreSQL案である。現行MVPの計画・受入条件には使わない。現行の実装・デプロイは[`gas/README.md`](../gas/README.md)、[`gas/REDEPLOY.md`](../gas/REDEPLOY.md)、[`docs/18`](18-test-specification.md)を正とする。

## マイルストーン
| 段階 | 内容 | 完了条件 |
|---|---|---|
| M1 | LINE受信、DB保存、重複排除 | 同一イベント再送で二重登録されない |
| M2 | AI構造化抽出、根拠紐付け、承認 | 提案と確定が混ざらない |
| M3 | Drive OAuth、月フォルダ、常設Docs/Sheets | 月替わりで正しいフォルダが1個作成される |
| M4 | 週次・月次レポート自動生成 | Docs生成後にURL付きLINE通知（週次） |
| M5 | 障害復旧、権限、監査、削除 | API障害後に再実行で重複が生じない |

## テストケース
1. 同一LINEイベントを2回受信してもメッセージは1件。
2. 「参加費1500円にしようかな」はCONFIRMEDにならない。
3. 担当者不明のタスクはNULLで保存。
4. 11月から12月へ移ると`2026-12`フォルダが1つだけ作られる。
5. 11/30〜12/06の週次レポートは`2026-11`に格納。
6. 12月に入っても11月からの未完了タスクが常設Sheetsに残る。
7. Google Docs API失敗時は成功通知を出さず再試行。
8. 同一週次ジョブを2回実行してもレポート文書が重複しない。
9. 会話がない週は不要なLINE投稿をしない。
10. `/bot 決定事項`は確定済みのものだけ回答する。
11. 週次レポートの集計締切を超えた発言も、次の集計に必ず含まれる。

## 実装前に確認する事項
- **週次配信時刻**：日曜20時の速報版か、月曜09時の確定版か。
- **Google Drive認証**：個人アカウントOAuthか、組織の共有ドライブか。
- **Google文書の閲覧者**：誰に権限を付けるか。
- **保存期間**：原文と生成物を何か月保持するか。
- **月次レポート通知**：Docs作成のみか、LINEにも投稿するか。
- **承認権限**：誰が決定候補を確定できるか。
- **費用上限**：クラウド/AI/APIの月額予算。

## 初回データ移行
既存のLINEエクスポートTXTは手動インポートを別機能として作る。発言者名の同一性、タイムゾーン、添付の欠落に注意し、抽出した決定候補はすべて人間確認を経て確定する。
