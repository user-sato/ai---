# 05 定期処理とLINE通知

## ジョブスケジュール（JST、仮設定）
| ジョブ | 実行時刻 | 動作 | LINE投稿 |
|---|---|---|---|
| message-analysis | 5分ごと、またはキュー起動 | 未解析会話をまとめて抽出 | なし |
| daily-reconcile | 毎日23:00 | 現況書・Sheets同期、未処理再試行 | なし |
| weekly-report | 毎週日曜20:00 | 前週月曜〜日曜のDocs生成、LINE要約 | あり |
| monthly-rollover | 毎月1日00:10 | 新月フォルダを自動作成 | なし |
| monthly-report | 毎月1日09:00 | 前月の月次Docs作成 | 初期はなし |
| overdue-check | 毎朝09:00 | 期限超過候補を抽出 | 初期は週次へ集約 |

## 週次レポートの期間
日曜20:00実行の場合、対象は「前週月曜00:00〜当週日曜20:00」ではなく、**直近の完了した週**に統一するか、**当週月曜00:00〜日曜20:00時点の暫定版**にする必要がある。初期案は**当週月曜00:00〜日曜20:00時点の速報版**とし、日曜20:00以降の発言は次回週次へ繰り越さず、月次集計に含め、翌週のレポートでは前回締切以降の差分として扱う。期間境界を明示するため `cutoff_at` を保存する。

## 推奨の改善案
完全な月曜〜日曜集計が必要なら**月曜09:00に前週の確定版を配信**する方がシンプル。どちらを採用するかは実装前に決める。レポート生成は`[period_start, period_end)`で一貫させ、未集計区間を作らない。

## LINE投稿テンプレート
```text
【AI書記｜週次レポート】
対象：YYYY/MM/DD〜YYYY/MM/DD（集計締切：YYYY/MM/DD HH:mm）
新規確定：N件 / 確認待ち：N件 / 未解決課題：N件

今週の要点
・...
・...

詳細議事録：<Google Docs URL>
タスク・残課題：<Google Sheets URL>
```

## 通知ルール
- 通常は静かに記録し、毎メッセージには反応しない。
- `/bot 残課題`、`/bot 決定事項`、`/bot 今週`、`/bot 確認待ち`等は明示要求として応答。
- 週次はレポートDocs生成と同期の成功後に送信。
- 新着ゼロの週は投稿しない（設定で変更可）。
- 確認待ちが多い場合も勝手に確定せず、週次レポートに記載。
- 障害・認証切れ・同期失敗は管理者向け通知。グループへ機密エラー情報を投稿しない。

## 重複防止
- `report_runs`に対象期間の一意制約。
- `notification_outbox`に送信予定・送信中・送信済みを保存。
- LINE APIの送信再試行は利用可能なリトライキー仕様を確認して実装する。
- LINE送信直後にプロセスが落ちた場合の二重投稿リスクを監視し、必要に応じて管理者確認へ回す。
