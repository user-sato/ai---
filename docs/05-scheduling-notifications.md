# 05 定期処理とLINE通知

## ジョブスケジュール（JST、仮設定）
| ジョブ | 実行時刻 | 動作 | LINE投稿 |
|---|---|---|---|
| message-analysis | 5分ごと、またはキュー起動 | 未解析会話をまとめて抽出 | なし |
| daily-reconcile | 毎日23:00 | 現況書・Sheets同期、未処理再試行 | なし |
| weekly-report | 毎週日曜20:00頃 | 前回締切以降のMarkdown生成、LINE要約 | あり |
| monthly-rollover | 毎月1日00:10 | 新月フォルダを自動作成 | なし |
| monthly-report | 毎月1日09:00 | 前月の月次Docs作成 | 初期はなし |
| overdue-check | 毎朝09:00 | 期限超過候補を抽出 | 初期は週次へ集約 |

## 週次レポートの期間
日曜20:00 JSTを締切として、前回締切から今回締切までの`[period_start, period_end)`を基本対象にする。日曜20:00以降の発言は次回へ入る。Webhook遅延などで前回締切後に届いた古い未報告発言も、欠落を防ぐため次回へ含める。`Reports`へ期間キー、対象Message ID、AI結果を保存し、同じ締切のレポートを重複生成しない。

## LINE投稿テンプレート
```text
【AI書記｜週次レポート】
対象：YYYY/MM/DD〜YYYY/MM/DD（集計締切：YYYY/MM/DD HH:mm）
新規確定：N件 / 確認待ち：N件 / 未解決課題：N件

今週の要点
・...
・...

週次レポート：<Google Drive Markdown URL>
```

## 通知ルール
- 通常は静かに記録し、毎メッセージには反応しない。
- Botを文頭メンションした`残課題`、`決定事項`、`進行方針`、`今週`、`確認待ち`等は明示要求として応答。
- 週次はMarkdown生成の成功後に、AI要約とURLを送信。
- 新着ゼロの週は投稿しない（設定で変更可）。
- 確認待ちが多い場合も勝手に確定せず、週次レポートに記載。
- 障害・認証切れ・同期失敗は管理者向け通知。グループへ機密エラー情報を投稿しない。

## 重複防止
- `Reports`に対象期間キーを1行だけ保存する。
- AI結果、送信状態、永続LINE retry keyを同じ行へ保存する。
- 一時失敗は5分処理で最大3回再試行する。
- LINE送信直後にプロセスが落ちた場合の二重投稿リスクを監視し、必要に応じて管理者確認へ回す。
