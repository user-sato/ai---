# 05 定期処理とLINE通知

## ジョブスケジュール（JST）
| ジョブ | 実行時刻 | 動作 | LINE投稿 |
|---|---|---|---|
| `processPendingMessages` | 5分ごと | 未解析会話、メンション依頼、再試行、週次回復 | 整理結果・失敗通知のみ |
| `createWeeklyReport` | 毎週日曜20:00頃 | 前回締切以降のMarkdown生成、LINE要約 | あり |

## 週次レポートの期間
日曜20:00 JSTを締切として、前回締切から今回締切までの`[period_start, period_end)`を基本対象にする。日曜20:00以降の発言は次回へ入る。Webhook遅延などで前回締切後に届いた古い未報告発言も、欠落を防ぐため次回へ含める。`Reports`へ期間キー、対象Message ID、AI結果を保存し、同じ締切のレポートを重複生成しない。

## LINE投稿形式

1回のPush APIリクエストに、次のテキストメッセージを3個入れて送る。

```text
（1個目）
【AI書記｜週次レポート】
対象: YYYY/MM/DD HH:mm JST〜YYYY/MM/DD HH:mm JST
新規確定: N件 / 現在の確認待ち: N件 / 現在の未解決: N件

（2個目）
<AI要約>

（3個目）
週次レポート: <Google Drive Markdown URL>
```

## 通知ルール
- 通常は静かに記録し、毎メッセージには反応しない。
- Botを文頭メンションした`残課題`、`決定事項`、`進行方針`、`今週`、`確認待ち`等は明示要求として応答。
- 週次はMarkdown生成の成功後に、AI要約とURLを送信。
- 新着も継続管理事項もない週は、AIを呼ばず「新しい動きなし」のMarkdownを作成し、そのURLを投稿する。
- 確認待ちが多い場合も勝手に確定せず、週次レポートに記載。
- 週次の最終失敗は対象グループへ機密を含まない固定文を投稿する。詳細は`Reports`とApps Script実行履歴で管理者が確認する。

## 重複防止
- `Reports`に対象期間キーを1行だけ保存する。
- AI結果、送信状態、永続LINE retry keyを同じ行へ保存する。
- 週次の一時失敗は5分処理で最大3回再試行する。
- LINE送信直後にプロセスが落ちた場合の二重投稿リスクを監視し、必要に応じて管理者確認へ回す。
